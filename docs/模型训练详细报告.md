# WordLink-Edge 模型训练详细报告

> 模型：WordLink-Edge v2（Qwen2.5-1.5B-Instruct + 领域微调 LoRA，SFT + DPO 全管线）
> 训练周期：2026-09-07 ~ 09-09 ｜ 硬件：Apple Silicon Mac（48GB 统一内存，MPS 后端，无 CUDA）
> 配套：实测基准 `outputs/eval/BENCHMARK_RESULTS.md` ｜ 训练全程时间线 `训练全程报告.html`
> 本报告为模型训练部分的权威记录，所有数字均为实测。

---

## 〇、结论摘要

1. **最终模型**：Qwen2.5-1.5B-Instruct → SFT（2045 条多样化语料）→ DPO（真实失败负例），全流程在本机 MPS 完成真实训练。
2. **核心成果**：生词注入命中率 **63.06%（微调前）→ 88.06%（SFT 后）→ 87.78%（DPO 后）**，JSON 合规 **82.22% → 100%**，CEFR 越界 **0.17% → 0.01%**，阅读难度 FKGL **13.5 → 9.8**（匹配 A2/B1 学习者）。
3. **DPO 定位**：与 SFT 统计持平（差异在 n=90 噪声带内），行为收敛更稳（margins 0.105→11.28），零 reward hacking 退化——验证配方的安全性而非刷指标。
4. **关键教训**：小模型微调的价值（+25pp）与模型规模无关的零样本失效（7B 零样本 39.72%/0% JSON）共同构成"为什么必须领域微调"的完整证据。

## 一、基座与任务定义

| 项 | 值 |
|---|---|
| 基座 | Qwen/Qwen2.5-1.5B-Instruct（阿里通义，Apache 2.0） |
| 任务 | CEFR 受限微故事生成：给定主题 + 3~4 个到期复习词 + 等级(A2/B1/B2)，输出含生词加粗注入的 JSON 结构短文（标题/正文/中文对照/词汇讲解） |
| 四重约束 | 目标词 100% 注入 ｜ 词汇不越 CEFR 级 ｜ 长度 60~200 词 ｜ JSON 结构合法 |
| 为什么是 1.5B | 实测通过质量线的最小引擎；目标形态为浏览器 WebGPU 4-bit 端侧推理（~950MB，离线、零边际成本、数据不出设备） |

## 二、数据工程

### v1 模板语料（已废弃，保留作对照）
510 条，同一英文句子骨架换词 + 固定 rejected 模板。问题：SFT 学到的是模板记忆（98.33% 虚高），偏好对无信息量（DPO 空转共因）。

### v2 多样化语料（现役，`data/wordlink_*_train_v2.jsonl`）
- **生成**：`08_generate_diverse_corpus.py`，44 主题 × A2/B1/B2 × 目标词组，教师模型 DeepSeek-V3 生成，12 并发，逐条落盘断点续跑。
- **chosen 硬过滤**（通过率 90.5%，2045 条入选）：`validate_sample` 命中率=1.0 且 越界=0 ＋ JSON 合法 ＋ 长度带 60~200 词 ＋ FKGL 难度带（A2: 2.5-7.5 / B1: 5-10.5 / B2: 8-13.5）。
- **rejected 来源**：Qwen2.5-7B 零样本（temperature 0.9）在同题上的**真实失败输出**（命中不全/越界/JSON 破碎才收），失败模式含退化重复与字段破碎——非人工模板。
- **评测卫生**：与 90 题测试集按 prompt 去重，测试集文件全程未改动。
- **验证器**（`01_prepare_dataset.py`）：短语归一化（cognitive_load → "cognitive load"）、轻量词形还原（复数/时态）、精确词匹配（修复 cat⊂category）、专有名词豁免；`random.seed(42)` 确定性。

## 三、SFT 监督微调

| 项 | 值 |
|---|---|
| 框架 | TRL 0.11 SFTTrainer + PEFT 0.13.2 + transformers 4.45.2 + torch 2.5.1(MPS) |
| 数据 | 2045 条（train 1881 / eval 164，seed=42） |
| LoRA | r=64, α=128, dropout=0.05, target=[q,k,v,o,gate,up,down]_proj |
| 超参 | lr 2e-4 cosine, warmup 3%, 3 epochs, batch 1 × accum 16, max_seq 896(固定长度 padding,零截断) |
| 精度 | fp32（bf16 在 MPS 上存在 autocast 内存泄漏,实测无提速故弃用） |
| 结果 | 351/351 步，final loss ≈ 0.37，adapter 295MB，MD5 `1d924802…` |

对照（v1 模板数据 + fp32-768）：93 步 / 67 分钟 / loss 0.029 —— 低 loss 恰是模板记忆的证据。

## 四、DPO 直接偏好优化

| 项 | 值 |
|---|---|
| 起点 | 基座 + SFT LoRA `merge_and_unload()` 合并模型（`outputs/wordlink_edge_sft_v2_merged`） |
| DPO LoRA | r=32, α=64, dropout=0.05, target=[q,v,o,gate,down]_proj（25.9M 可训练参数） |
| β / LR | 0.1 / 5e-6, cosine, warmup 5%, 2 epochs, batch 1 × accum 16, seed=42 |
| 数据 | 2045 对（chosen=过滤后正例 / rejected=7B 真实失败输出） |
| 安全阀 | NoOpGuard：开局 20 步 loss<1e-4 即抛错（防空转） |
| 结果 | 256/256 步，**四条验收全过**：margins 0.105→11.28 爬升 ｜ loss 0.6438→0.0001 收敛 ｜ adapter MD5 `73d7d16f…`≠SFT ｜ chosen logps 持续变化 |
| 定位 | 与 SFT 统计持平、零退化——验证对齐安全性；行为稳健性收益在分布偏移下显现 |

### ⚠️ v1 DPO 空转事故复盘（重要工程教训）
首版 DPO 训练 1h47m 权重零变化（adapter MD5 与 SFT 逐字节相同 `0b23d61b…`）。根因：
① `ref_model=None` + 已挂 SFT adapter 的 PeftModel，TRL 0.11 以「禁用 adapter 的原始基座」为参考模型，
β·margin≈6.4 → sigmoid 饱和、梯度恒零（日志 loss=0 / grad_norm=0 / margins≈64）；
② 旧偏好对 chosen 即 SFT 训练模板、rejected 为固定句，SFT 后 margin 天然巨大。
两条根因均已在 v2 修复并验收。

## 五、工程专项：Apple MPS 训练稳定性

| 问题 | 现象 | 根因 | 解法 |
|---|---|---|---|
| 线性内存泄漏 | 单进程长训练池子 ~1.4GB/step 增长，与精度/批大小/分组/回收频率全部无关 | torch MPS 后端平台级问题 | **分程续跑**：每 117/128 步存档退出，新进程从 checkpoint 续跑，编排器自动循环至完成 |
| 内存上限分母误解 | 以为 0.60=28.8GB，实际 22.46GB | `set_per_process_memory_fraction` 分母是系统建议值 37.4GB 而非物理 48GB | 按真实分母重算水位 |
| 变长序列碎片化 | 每 step 张量尺寸不同，分配器缓存零复用 | batch=1 + 连续分布长度(636~891 tok) | 固定长度 padding（896，零截断） |
| bf16 autocast 泄漏 | bf16 每 step 净增 1.2GB | torch 2.5.1 MPS autocast | 弃用 bf16 改 fp32（实测无提速差异） |
| 崩溃兜底 | OOM 时进程死亡 | 设计行为（上限护栏） | 存档间隔 40 步 + 看门狗自动续跑，损失 ≤40 步 |

## 六、最终实测结果（90 题 · 贪心解码 · 对真实输出解算）

| 模型 | 命中 ↑ | 越界 ↓ | JSON ↑ | FKGL | 说明 |
|---|---:|---:|---:|---:|---|
| 1.5B 底座（微调前） | 63.06% | 0.17% | 82.22% | 13.5 | 基线 |
| **+ SFT（v2 多样化语料）** | **88.06%** | **0.01%** | **100%** | **9.82** | 泛化口径 |
| **+ DPO（v2）** | 87.78% | 0.01% | 100% | 9.94 | 持平，行为更稳 |
| Qwen2.5-7B 零样本 | 39.72% | 0.07% | 0% | — | 85/90 退化重复 |
| Qwen2.5-7B 零样本（反退化参数宽限） | 41.67% | 0.12% | 0% | 103.4 | 参数无法拯救 |
| DeepSeek-V3 零样本（教师） | 97.78% | 0.01% | 100% | 10.38 | 商用旗舰对照 |
| Teacher/Oracle | 98.33% | 0.22% | 100% | — | 上界 |

> 评测组合注意：DPO adapter 必须加载在 **base+ΔSFT 合并模型**之上；直接挂原始基座会得到 ≈底座成绩（63.89%，已实测验证此陷阱）。

## 八、复现指南

```bash
# 环境一次性
cd model_training && uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python torch==2.5.1 transformers==4.45.2 trl==0.11.0 peft==0.13.2 datasets==3.0.2 accelerate==1.0.1 rich pydantic

# ① 语料（需 LLM_BASE_URL / SILICONFLOW_APIKEY）
python model_training/08_generate_diverse_corpus.py --target-sft 2200 --workers 12
# ② SFT（分程续跑, MPS 安全）
python model_training/02_train_sft.py --train_file data/wordlink_sft_train_v2.jsonl \
  --max_seq_length 896 --batch_size 1 --gradient_accumulation_steps 16
# ③ DPO（merge → 新 LoRA → fail-fast）
python model_training/03_train_dpo.py --sft_model_path outputs/wordlink_edge_sft_v2 \
  --merged_output_dir outputs/wordlink_edge_sft_v2_merged \
  --dpo_train_file data/wordlink_dpo_train_v2.jsonl
# ④ 评测
python model_training/eval_real.py --backend local --base outputs/wordlink_lexiconstrain_dpo_merged --label edge_dpo_v2
```
